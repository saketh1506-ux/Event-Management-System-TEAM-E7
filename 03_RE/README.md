# Requirements Engineering

Purpose: Functional and non-functional requirements and their traceability.

## Available requirements documents

- [`Functional_Requirements.md`](Functional_Requirements.md) — readable extract of the user, organizer, administrator, and system functional requirements.
- [`Non_Functional_Requirements.md`](Non_Functional_Requirements.md) — readable extract of quality and security requirements.
- [`13_Requirements_Traceability_Matrix.docx`](13_Requirements_Traceability_Matrix.docx) — maps requirements to use cases and test cases.
- The formal SRS remains the source of truth: [`04_Software_Requirements_Specification.docx`](../01_SRS_WBS/04_Software_Requirements_Specification.docx).

The Markdown files are navigation-friendly extracts, not replacements for the approved SRS or a statement that every requirement is implemented.
